# نظام أرشفة والبحث في ملفات الإكسل

تطبيق داخلي عربي لأرشفة ملفات Excel المتغيرة الأعمدة داخل PostgreSQL، ثم البحث عن الأشخاص عبر جميع الملفات بالاسم أو الرقم الوطني أو الهاتف أو أي حقل قياسي. يحتفظ النظام بالقيم الأصلية كما وردت، ويستخدم قيم ظل مطبّعة للبحث العربي السريع وربط سجلات الشخص نفسه بين الملفات.

## المتطلبات

- Node.js 20 أو أحدث (بيئة التطوير الحالية Node.js 24).
- Docker Desktop لتشغيل PostgreSQL 16، أو PostgreSQL 16+ مثبت محليًا.
- مساحة كافية لقاعدة البيانات والنسخ الاحتياطية.

## التشغيل لأول مرة

1. انسخ ملف البيئة:

   ```powershell
   Copy-Item .env.example .env
   ```

2. افتح `.env` وغيّر `SESSION_SECRET` إلى قيمة عشوائية طويلة، وغيّر اسم المستخدم وكلمة المرور الافتراضيين قبل إتاحة التطبيق على الشبكة.
3. شغّل PostgreSQL:

   ```powershell
   docker compose up -d
   ```

   إذا كنت تستخدم PostgreSQL 16+ المثبّت محليًا بدل Docker، نفّذ العبارتين الآتيتين مرة واحدة بحساب مسؤول قاعدة البيانات، ثم أبقِ `DATABASE_URL` الافتراضي في `.env`:

   ```sql
   CREATE ROLE excel_archive LOGIN PASSWORD 'excel_archive';
   CREATE DATABASE excel_archive OWNER excel_archive ENCODING 'UTF8' TEMPLATE template0;
   ```

4. ثبّت الحزم، وأنشئ الجداول وفهارس البحث:

   ```powershell
   npm install
   npm run db:push
   ```

5. اختياريًا، أضف بيانات عربية تجريبية:

   ```powershell
   npm run db:seed
   ```

6. شغّل التطبيق:

   ```powershell
   npm run dev
   ```

ثم افتح [http://localhost:3000](http://localhost:3000). القيم الافتراضية للتجربة فقط هي `admin` و`admin123`.

## التشغيل باستخدام migrations

للخادم المحلي الثابت يمكن تطبيق migration الكاملة بدل `db:push`:

```powershell
npm run db:migrate
npm run build
npm start
```

Migration الأولى تنشئ `pg_trgm` والجداول والفهارس، وتضيف migration لاحقة حقل رمز العقد الثانوي. أمر `db:push` يشغّل أيضًا ملف SQL idempotent لضمان وجود فهارس GIN الأحد عشر.

## طريقة الاستخدام

- أنشئ مجموعة من صفحة «المجموعات».
- ارفع ملفًا من صفحة «رفع ملف»، واختر ورقة واحدة واربط الحقول القياسية والفئات.
- راقب تقدم الاستيراد؛ يمكن مغادرة الصفحة والعودة إلى المهمة.
- راجع تقرير الجودة بعد اكتمال الرفع.
- افتح «تضارب البيانات» لفحص جميع الملفات: اختر بيانات خاطئة أو ناقصة أو تشابه أسماء أو تضارب بيانات، ثم الحقل والحالة الفرعية. يعرض الجدول المصدر وصف Excel والاسم الثلاثي واسم الأم والرقم الوطني الأصلي وشرح المشكلات، مع روابط للسجل والملف.
- ابحث بالاسم أو الرقم، وافتح أي نتيجة لرؤية القيم الأصلية والملفات الأخرى للشخص نفسه.
- استخدم «تحديث» لرفع إصدار جديد. البنية المطابقة تستبدل الصفوف، والبنية المختلفة تنشئ إصدارًا بديلًا بعد ربط الأعمدة.
- نزّل نسخة JSON دورية من «النسخ الاحتياطي والاستعادة» واحتفظ بها خارج جهاز الخادم.

## ملاحظات Excel

- الصف الأول هو صف العناوين دائمًا، ويجب أن تكون أسماء الأعمدة غير مكررة.
- الخلايا تقرأ كنصوص لحماية الأصفار البادئة والمعرفات الطويلة.
- ExcelJS يدعم `.xlsx`. إذا كان ملف `.xls` قديمًا بصيغة BIFF فافتحه في Excel أو LibreOffice واحفظه كـ `.xlsx` أولًا.
- الملف الواحد يستورد ورقة واحدة فقط في كل مرة.

## التحقق والصيانة

```powershell
npm test
npm run typecheck
npm run build
```

لفحص قواعد تضارب البيانات الـ31 على PostgreSQL المحلي نفّذ `npm run test:conflicts`. يستخدم الفحص جداول مؤقتة داخل اتصال مستقل، ولا يغيّر بيانات الأرشيف. يحتاج إلى `.env` وقاعدة البيانات المهيأة.

في صفحة التضارب، الشخص هو «الاسم الثلاثي + اسم الأم» بعد التطبيع، وفحص تركيب الاسم يعتمد «الاسم + اسم الأب + النسبة». الرقم الوطني من 9 إلى 11 رقماً لا يعد خطأ طول، والشام كاش يجب أن يحتوي على 16 رقماً فقط. تفحص التواريخ غير الفارغة من 01/01/1940 حتى اليوم. فحص فراغ حقول الاسم الأربعة مشروط بربطها بأعمدة Excel، بينما الرقم الوطني والشام كاش والرقم الذاتي واسم الأم تفحص في جميع السجلات. النتائج تحتسب مباشرة عند اختيار الفلاتر أو «تحديث الفحص».

لفحص استخدام فهرس trigram بعد تعبئة قاعدة البيانات، افتح `psql` على قاعدة `excel_archive` ونفّذ مثلًا:

```sql
EXPLAIN (ANALYZE, BUFFERS)
SELECT id
FROM records
WHERE n_full_name ILIKE '%احمد%';
```

يفترض أن تظهر خطة من نوع `Bitmap Index Scan` على `records_n_full_name_trgm_idx` للعبارات المناسبة. نفّذ `ANALYZE records;` بعد استيراد كمية كبيرة إذا اختار PostgreSQL خطة قديمة، ثم أعد الفحص. الأنماط القصيرة جدًا قد تختار مسحًا تسلسليًا لأن المخطط يقدره أقل كلفة.

## الأمان والنسخ الاحتياطي

- التطبيق يملك حساب مسؤول واحد من متغيرات البيئة، ولا يحتوي تسجيل مستخدمين أو أدوارًا.
- cookie الجلسة موقّعة و`httpOnly`، وتصبح `secure` في وضع الإنتاج.
- لا تضع `.env` أو نسخ JSON أو ملفات Excel الأصلية داخل مستودع عام.
- الاستعادة عملية استبدال كاملة؛ نزّل نسخة جديدة قبل تنفيذها.
- مهام الرفع التشغيلية محفوظة كتاريخ في النسخة، لكن الملف المؤقت نفسه لا يصدّر. لذلك تتحول أي مهمة غير مكتملة عند الاستعادة إلى حالة فشل واضحة.

## بنية المشروع

- `app/`: الصفحات وواجهات API والمصادقة.
- `components/`: واجهة RTL ومكونات shadcn والبحث والرفع.
- `lib/`: Prisma، التطبيع العربي، Excel، البحث الخام، النسخ الاحتياطي، والإجراءات.
- `prisma/`: النموذج، migration، فهارس `db:push`، والبيانات التجريبية.
- `PLAN.md` و`PROGRESS.md`: المواصفات الكاملة وسجل تنفيذ المشروع.
