# نظام أرشفة والبحث في ملفات الإكسل

تطبيق داخلي عربي لأرشفة ملفات Excel المتغيرة الأعمدة داخل PostgreSQL، ثم البحث عن الأشخاص عبر جميع الملفات بالاسم أو الرقم الوطني أو الهاتف أو أي حقل قياسي. يحتفظ النظام بالقيم الأصلية كما وردت، ويستخدم قيم ظل مطبّعة للبحث العربي السريع وربط سجلات الشخص نفسه بين الملفات.

## المتطلبات

- Node.js 20 أو أحدث (بيئة التطوير الحالية Node.js 24).
- Docker Desktop لتشغيل PostgreSQL 16، أو PostgreSQL 16+ مثبت محليًا.
- مساحة كافية لقاعدة البيانات والنسخ الاحتياطية.

## التشغيل لأول مرة

1. انسخ ملف البيئة:

   ```powershell
   Copy-Item .env.example .env
   ```

2. افتح `.env` وحدد `ADMIN_USERNAME` و`ADMIN_PASSWORD` لتسجيل الدخول. لا يحتاج التطبيق إلى `SESSION_SECRET`.
3. شغّل PostgreSQL:

   ```powershell
   docker compose up -d
   ```

   إذا كنت تستخدم PostgreSQL 16+ المثبّت محليًا بدل Docker، نفّذ العبارتين الآتيتين مرة واحدة بحساب مسؤول قاعدة البيانات، ثم أبقِ `DATABASE_URL` الافتراضي في `.env`:

   ```sql
   CREATE ROLE excel_archive LOGIN PASSWORD 'excel_archive';
   CREATE DATABASE excel_archive OWNER excel_archive ENCODING 'UTF8' TEMPLATE template0;
   ```

4. ثبّت الحزم، وأنشئ الجداول وفهارس البحث:

   ```powershell
   npm install
   npm run db:push
   ```

5. اختياريًا، أضف بيانات عربية تجريبية:

   ```powershell
   npm run db:seed
   ```

6. شغّل التطبيق:

   ```powershell
   npm run dev
   ```

ثم افتح [http://localhost:3000](http://localhost:3000). القيم الافتراضية للتجربة فقط هي `admin` و`admin123`.

للدخول من أجهزة الشبكة استخدم `http://عنوان-IP-الخادم:3000` مع اسم المستخدم وكلمة المرور نفسيهما. يستمع `npm run dev` و`npm start` على جميع واجهات الشبكة. لكل متصفح جلسة مستقلة مدتها 12 ساعة، وتعمل ملفات تعريف الارتباط عبر HTTP المحلي وHTTPS. يشتق التطبيق مفتاح توقيع الجلسة تلقائياً من بيانات الدخول؛ تغييرها وإعادة تشغيل الخادم يُبطل الجلسات السابقة.

## التشغيل باستخدام migrations

للخادم المحلي الثابت يمكن تطبيق migration الكاملة بدل `db:push`:

```powershell
npm run db:migrate
npm run db:generate
npm run build
npm start
```

Migration الأولى تنشئ `pg_trgm` والجداول والفهارس، وتضيف migrations لاحقة حقول العقود والتخزين الرقمي للشام كاش والرقم الوطني. لترقية قاعدة موجودة استخدم `db:migrate` كي تُحوّل الأرقام الوطنية القديمة وتُعاد حسابات الجودة، ثم `db:generate` وأعد تشغيل التطبيق. أمر `db:push` مخصص لتهيئة المخطط ويشغّل أيضًا ملف SQL idempotent لضمان وجود فهارس GIN الأحد عشر.

## طريقة الاستخدام

- أنشئ مجموعة من صفحة «المجموعات».
- ارفع ملفًا من صفحة «رفع ملف»، واختر ورقة واحدة أو عدة أوراق مترابطة بالرقم الوطني، ثم اربط الحقول القياسية والفئات.
- راقب تقدم الاستيراد؛ يمكن مغادرة الصفحة والعودة إلى المهمة.
- راجع تقرير الجودة بعد اكتمال الرفع.
- افتح «تضارب البيانات» لفحص جميع الملفات: اختر بيانات خاطئة أو ناقصة أو تشابه أسماء أو تضارب بيانات، ثم الحقل والحالة الفرعية. يعرض الجدول المصدر وصف Excel والاسم الثلاثي واسم الأم والرقم الوطني المنسق وشرح المشكلات، مع روابط للسجل والملف.
- ابحث بالاسم أو الرقم، وافتح أي نتيجة لرؤية القيم الأصلية والملفات الأخرى للشخص نفسه.
- استخدم «تحديث» لرفع إصدار جديد. البنية المطابقة تستبدل الصفوف، والبنية المختلفة تنشئ إصدارًا بديلًا بعد ربط الأعمدة.
- نزّل نسخة JSON دورية من «النسخ الاحتياطي والاستعادة» واحتفظ بها خارج جهاز الخادم.

## ملاحظات Excel

- الصف الأول هو صف العناوين دائمًا، ويجب أن تكون أسماء الأعمدة غير مكررة.
- الخلايا تقرأ كنصوص لحماية الأصفار البادئة والمعرفات الطويلة.
- خلايا المعادلات تقرأ من النتيجة المحفوظة في Excel، ولا يستورد نص المعادلة. تشمل القراءة المعاينة والربط والاستيراد، وتحافظ على نتائج `0` و`false` والقيم الفارغة. إذا لم توجد نتيجة محفوظة، تظهر رسالة باسم الورقة والخلية تطلب إعادة حساب الملف وحفظه؛ التطبيق لا يحسب المعادلات أو يجلب روابط خارجية. إذا رجعت المعادلة رقماً تسلسلياً قصيراً بدلاً من الرقم الوطني، يبقى خطأ تكامل وتعرض رسالة الربط القيمة المقروءة.
- ExcelJS يدعم `.xlsx`. إذا كان ملف `.xls` قديمًا بصيغة BIFF فافتحه في Excel أو LibreOffice واحفظه كـ `.xlsx` أولًا.
- يدعم الملف ورقة واحدة أو دمج عدة أوراق في سجل واحد لكل صف أساسي.

### رفع عدة أوراق مترابطة

1. افحص المصنف، ثم اختر «عدة أوراق مترابطة بالرقم الوطني» من «طريقة الاستيراد».
2. الورقة الأولى هي الأساسية. اختر عمود الرقم الوطني فيها؛ يمكن أن يكون في أي موضع.
3. اختر أي عدد من الأوراق الإضافية. يجب أن يحتوي العمود الأول في كل منها على الرقم الوطني، وبقية الأعمدة على المعلومات المرتبطة.
4. اضغط «معاينة وربط الأوراق»، ثم أكمل ربط حقول البحث والفئات والمعاينة والتأكيد المعتاد.

تُطابق القيمة الرقمية بعد تحويل الأرقام العربية والفارسية وحذف الفراغات والأصفار اليسارية؛ `123456789` و`00123456789` مفتاح واحد. يجب أن يكون مفتاح الربط صالحاً (9–11 رقماً). إذا تكرر مفتاح صالح في الأساسية أو في ورقة إضافية، أو كان صف إضافي بلا مفتاح صالح أو بلا مقابل أساسي، يتوقف الربط وتظهر الورقة ورقم الصف. السجل الأساسي الذي لا يقابله صف إضافي يبقى محفوظاً وتُترك أعمدة تلك الورقة فارغة؛ الأرقام الأساسية غير الصالحة تبقى لمراجعتها في تقرير الجودة.

تُرتب الأعمدة حسب ترتيب الأوراق داخل المصنف، ويُستبعد عمود الربط الأول من كل ورقة إضافية. عند تكرر عنوان عمود يضاف اسم ورقته مثل `المسمى الوظيفي [العمل]` دون استبدال القيمة الأساسية. يبقى رقم صف المصدر هو رقم الصف في الورقة الأساسية. الخيار نفسه متاح عند تحديث الملف، وتبقى النسخة السابقة حتى ينجح الاستيراد. الربط اختياري ومحفوظ في بيانات مهمة الرفع؛ النسخ القديمة ذات الورقة الواحدة تستمر بالعمل. الرفع المتعدد يقرأ المصنف للربط في الذاكرة ضمن حد الملف الحالي (50 ميغابايت)، ثم يحفظ السجلات بدفعات؛ رفع الورقة الواحدة يستمر بالقارئ التدريجي.

### دمج صفحات ملف اكسيل (قسم معزول)

قسم مستقل في `/merge-sheets` لا يقرأ ولا يكتب في قاعدة بيانات الأرشيف ولا يحفظ شيئاً على القرص: الملف والنتائج وملف التصدير جلسة مؤقتة في الذاكرة تختفي عند إعادة تشغيل الخادم.

1. ارفع ملف Excel واحد يحتوي على **أكثر من صفحة**. يُلغى عامل التصفية من جميع الأعمدة والصفوف، وتُظهر الصفوف والأعمدة المخفية.
2. الصفحة الأولى هي الصفحة الرئيسية. يُقترح عمود الرقم الوطني فيها تلقائياً من عنوان العمود وقيمه، ويمكن تغييره يدوياً.
3. اختر أي عدد من الصفحات الأخرى — صفحتان أو ثلاث أو أكثر. يجب أن يكون العمود الأول في كل منها هو الرقم الوطني الذي يربطها بالرئيسية.
4. اضغط «دمج الصفحات»: تظهر نسبة تقدم الرفع والمعالجة والتصدير، ثم عدد الأسطر ونسبة الربط وقيم الأسطر التي تعذر ربطها في كل صفحة.

قاعدة الربط: تُقرأ قيمة الخلية وتُحوَّل إلى رقم (تحويل الأرقام العربية، حذف الفراغات والفواصل والأصفار البادئة)، ويجب أن يكون الرقم أكثر من 7 محارف، وألا يتكرر داخل الصفحة الواحدة. ملف التصدير `دمج-الصفحات-التاريخ.xlsx` يحتوي على صفحة «الدمج» (أعمدة الصفحة الأولى ثم أعمدة كل صفحة أخرى بدون عمودها الأول) وصفحة «غير مرتبط» لكل صفحة فيها أسطر لم تُربط، وبتنسيق التصدير المعتمد في بقية النظام.

## التحقق والصيانة

```powershell
npm test
npm run typecheck
npm run build
```

لفحص قواعد تضارب البيانات الـ31 على PostgreSQL المحلي نفّذ `npm run test:conflicts`. يستخدم الفحص جداول مؤقتة داخل اتصال مستقل، ولا يغيّر بيانات الأرشيف. يحتاج إلى `.env` وقاعدة البيانات المهيأة.

للتجربة الكاملة للرفع متعدد الأوراق شغّل التطبيق محلياً ثم `npm run test:linked-import`. ينشئ الفحص مجموعة اختبار فريدة، ويتحقق من المعاينة والاستيراد والبحث والتفاصيل والتحديث وفشل الربط، ثم يحذف مجموعته وملفاته ومهامه فقط.

يُخزّن الرقم الوطني القياسي في `sf_national_id` كـ`BIGINT` بعد تحويل الأرقام العربية والفارسية وحذف الفراغات. يُفحص عدد أرقام قيمته العددية قبل تعبئة الأصفار: 9–11 صالح، و8 أو أقل أو 12 أو أكثر مشكلة تكامل، وكذلك أي محارف غير رقمية. يظهر في البحث والتضارب والتفاصيل بـ11 خانة: `123456789` ← `00123456789`، دون اقتطاع الأرقام الأطول. يبقى أصل Excel في JSON لتفسير الأخطاء، ويستخدم `d_national_id` كنص منسق مفهرس للبحث، و`national_id_num` للربط بالقيم الصحيحة فقط. القيم التي تتجاوز سعة BIGINT تحفظ في الأصل مع مشكلة تكامل دون تقريب. استعادة النسخ القديمة تطبق القاعدة نفسها. فحص الترحيل المعزول: `npm run test:national-id-migration`.

في صفحة التضارب، الشخص هو «الاسم الثلاثي + اسم الأم» بعد التطبيع، وفحص تركيب الاسم يعتمد «الاسم + اسم الأب + النسبة». الرقم الوطني من 9 إلى 11 رقماً لا يعد خطأ طول، والشام كاش يجب أن يحتوي على 16 رقماً بعد تحويل الأرقام العربية وحذف جميع الفراغات، بما فيها التبويب والأسطر الجديدة. تعتمد مقارنات الشام كاش التنظيف نفسه، مع الحفاظ على الأصفار البادئة في فحص الطول واعتبار الحروف والرموز أخطاء. تفحص التواريخ غير الفارغة من 01/01/1940 حتى اليوم. فحص فراغ حقول الاسم الأربعة مشروط بربطها بأعمدة Excel، بينما الرقم الوطني والشام كاش والرقم الذاتي واسم الأم تفحص في جميع السجلات. النتائج تحتسب مباشرة عند اختيار الفلاتر أو «تحديث الفحص».

لفحص استخدام فهرس trigram بعد تعبئة قاعدة البيانات، افتح `psql` على قاعدة `excel_archive` ونفّذ مثلًا:

```sql
EXPLAIN (ANALYZE, BUFFERS)
SELECT id
FROM records
WHERE n_full_name ILIKE '%احمد%';
```

يفترض أن تظهر خطة من نوع `Bitmap Index Scan` على `records_n_full_name_trgm_idx` للعبارات المناسبة. نفّذ `ANALYZE records;` بعد استيراد كمية كبيرة إذا اختار PostgreSQL خطة قديمة، ثم أعد الفحص. الأنماط القصيرة جدًا قد تختار مسحًا تسلسليًا لأن المخطط يقدره أقل كلفة.

## الأمان والنسخ الاحتياطي

- التطبيق يملك حساب مسؤول واحد من متغيرات البيئة، ولا يحتوي تسجيل مستخدمين أو أدوارًا.
- cookie الجلسة موقّعة و`httpOnly`، وتصبح `secure` في وضع الإنتاج.
- لا تضع `.env` أو نسخ JSON أو ملفات Excel الأصلية داخل مستودع عام.
- الاستعادة عملية استبدال كاملة؛ نزّل نسخة جديدة قبل تنفيذها.
- مهام الرفع التشغيلية محفوظة كتاريخ في النسخة، لكن الملف المؤقت نفسه لا يصدّر. لذلك تتحول أي مهمة غير مكتملة عند الاستعادة إلى حالة فشل واضحة.

## بنية المشروع

- `app/`: الصفحات وواجهات API والمصادقة.
- `components/`: واجهة RTL ومكونات shadcn والبحث والرفع.
- `lib/`: Prisma، التطبيع العربي، Excel، البحث الخام، النسخ الاحتياطي، والإجراءات.
- `lib/sheet-merge/` و`components/sheet-merge/`: قسم «دمج صفحات ملف اكسيل» المعزول — جلسة مؤقتة في الذاكرة بلا قاعدة بيانات وبلا ملفات على القرص.
- `prisma/`: النموذج، migration، فهارس `db:push`، والبيانات التجريبية.
- `PLAN.md` و`PROGRESS.md`: المواصفات الكاملة وسجل تنفيذ المشروع.
